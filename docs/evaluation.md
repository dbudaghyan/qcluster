# Understanding the Evaluation Results

After running the QCluster pipeline, a new directory is created in the location specified by the `EVALUATION_RESULTS_DIR` environment variable. This directory contains a comprehensive set of files that allow you to analyze and understand the performance of the clustering algorithm.

Each evaluation run is stored in a unique folder named with the timestamp of the run and the git hash of the commit that was evaluated (e.g., `20231027-120000-abcdef1`). This ensures that every result is fully reproducible.

## Structure of the Results Directory

Here is a breakdown of the files you will find in each evaluation directory:

-   **`.env`**: A copy of the environment variables used for this specific run. This is crucial for reproducibility, as it captures the exact configuration of the pipeline.

-   **`clusters.json`**: A JSON file containing the generated clusters. For each cluster, it includes the title, a detailed description, and the number of questions it contains. This file gives you a qualitative understanding of the topics that were identified in your dataset.

-   **`cluster_to_class_scores.csv`**: This CSV file contains statistics that measure the similarity between the generated clusters and the original categories in the dataset. It provides metrics like the Jaccard score, which can help you assess how well the clusters align with the ground truth.

-   **`final_report.md`**: A qualitative report automatically generated by a large language model. This report provides a summary of the clustering results, highlighting the key findings and potential areas for improvement.

-   **`git_diff.txt`**: If there were any uncommitted changes in your local repository when you ran the pipeline, this file will contain the git diff. This helps to ensure that you can always trace back the exact code that produced the results.

-   **`main_script_*.py` / `main_script_*.ipynb`**: A copy of the entrypoint script or Jupyter Notebook that was used to run the pipeline. This is another key element for reproducibility.

-   **`pycm.zip`**: A zip file containing the serialized `pycm` confusion matrix object. You can deserialize this file to programmatically access the confusion matrix and all its associated statistics.

-   **`results.html`**: A user-friendly HTML report of the confusion matrix. This provides a visual representation of the clustering performance, making it easy to see which categories are being confused with each other.

-   **`stats.csv`**: A CSV file containing a wide range of statistics for each class, including precision, recall, F1-score, and many others. This file is useful for a detailed quantitative analysis of the results.

-   **`stats.pycm`**: A text file with a summary of the confusion matrix statistics, providing a quick overview of the overall performance.

-   **`stats_matrix.csv`**: The raw confusion matrix in CSV format, without any labels or additional statistics.

## Reproducing Results

To reproduce the results of a specific evaluation run, you can use the files in the corresponding directory:

1.  **Check out the correct commit:** Use the git hash from the directory name to check out the exact version of the code that was used.
2.  **Apply the git diff:** If the `git_diff.txt` file is not empty, apply the diff to your local files to restore any uncommitted changes.
3.  **Set the environment variables:** Use the `.env` file to set the environment variables to the same values that were used for the original run.
4.  **Run the pipeline:** Execute the `main_script_*.py` or `main_script_*.ipynb` file to re-run the pipeline and generate the exact same results.
